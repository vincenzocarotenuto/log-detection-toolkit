# Log Detection Toolkit

A small toolkit for detecting suspicious patterns in SSH authentication logs —
brute-force attempts, off-hours logins, and successful logins that follow a
burst of failures. Implemented in both **Python** and **SQL**, since real SOC
environments often need both approaches (scripting for automation, SQL for
querying data already sitting in a database or SIEM backend).

## Why this project
This replicates a core SOC analyst task: going through authentication logs to
separate normal activity from real threats. Doing this manually across
thousands of log lines isn't feasible — this is a small-scale version of what
detection rules in a SIEM do automatically.

## What it detects
1. **Brute-force attempts** — an IP address with an unusually high number of
   failed logins within a short time window (default: 10 failures in 5
   minutes, both configurable).
2. **Off-hours logins** — successful logins outside normal working hours
   (default: outside 07:00–21:00), which can indicate a compromised account
   or unauthorized access.
3. **Success after failures** — a successful login for an IP that had several
   recent failed attempts, a possible sign that a brute-force attempt
   eventually guessed the correct credentials.

## Project structure
```
log-detection-toolkit/
├── detect.py                    # main Python detection script
├── generate_sample_log.py       # generates the synthetic sample log
├── data/
│   └── sample_auth.log          # synthetic SSH auth log (normal traffic + simulated attack)
├── sql/
│   ├── detection_queries.sql    # same detection logic, written in SQL
│   └── load_log_to_sqlite.py    # loads the log into SQLite and runs the SQL queries
└── output/
    ├── alerts.csv               # generated by detect.py
    └── auth_events.db           # generated by load_log_to_sqlite.py
```

## Sample data
`data/sample_auth.log` is **synthetic** data generated by
`generate_sample_log.py` — not a real server's logs. It mixes a week of
normal login activity with a simulated brute-force attack (48 rapid failed
attempts from a single IP) and two off-hours logins, so the detection logic
has realistic patterns to catch. This keeps the project fully runnable and
shareable without exposing any real system data.

## Usage

### Python version
```bash
python3 detect.py data/sample_auth.log
```
Optional flags:
```bash
python3 detect.py data/sample_auth.log --fail-threshold 5 --window-minutes 3
```
Writes a full report to `output/alerts.csv`.

### SQL version
```bash
python3 sql/load_log_to_sqlite.py data/sample_auth.log
```
This loads the log into a local SQLite database and runs all four queries
from `sql/detection_queries.sql`, printing the results — including a brute-
force detection, off-hours logins, success-after-failures, and a per-IP
summary table.

### Regenerating the sample log
```bash
python3 generate_sample_log.py
```

## Design notes / limitations
- Detection thresholds (fail count, time window, working hours) are simple
  and configurable — a real SIEM would tune these per environment and combine
  them with additional context (geolocation, user baseline behavior, etc.).
- The brute-force detection uses a sliding window in Python and a fixed
  5-minute bucket approximation in SQL — worth knowing the difference: a
  bucket approach can split an attack across two buckets and under-count it,
  which the Python version avoids.
- This is intentionally kept dependency-free (Python standard library only)
  so it runs anywhere without a `pip install` step.
